# Private Library deployment

The frontend lives at `https://tools.cjaffa.com/333/`. It is a public login shell,
with no catalog, thumbnails, credentials or user records bundled into it. All
private data and playback authorization come from this separate API.

The existing GitHub Pages site, its `CNAME`, its DNS-only record and its routes
stay in place. **Never deploy this API on tools.cjaffa.com or put any Worker,
Pages project or reverse proxy in front of that hostname.**

## What is implemented

- Administrator-created accounts, scrypt password hashes, opaque server sessions,
  host-only secure HttpOnly cookies, CSRF checks and strict origin checks.
- Yoti hosted age verification. Only the server's authenticated results request
  can create an age grant, bound to the current login session and its random
  reference. Browser callback parameters do not grant access.
- Browsing, search, categories, per-account favorites, watch history, history
  deletion and saved playback position, backed by SQLite.
- Bunny Stream metadata and short-lived signed HLS playback for separately
  licensed, worldwide, full-length videos authorized for a custom player.
- Native HLS when Safari advertises support, otherwise the locally vendored
  hls.js 1.6.13 player. Playback starts on a user action, supports inline iPhone
  playback and renews access before expiry while keeping the current position.

## Content authorization comes first

Bunny is a delivery service, **not a licensed catalog supplier**. No commercial
catalog API or redistribution license has been established for this project.
Nothing in the code, a provider subscription, an affiliate API, or a license
record grants content rights. Do not use promotional clips as full-length titles.

Before importing a title, retain a contract or other evidence authorizing its
full-length playback, metadata, thumbnails, audience, hosting and native custom
HLS delivery. Upload only the authorized full-length file to your own Bunny
library. This adapter does not scrape or copy a third-party catalog, fetch
original files, download MP4 fallbacks, remove encryption, or alter DRM.

This first adapter deliberately rejects titles with regional-only rights,
expired licenses, missing declarations, or required DRM. It has no trusted
geolocation service or DRM entitlement adapter. Add those through documented
provider APIs before enabling such titles. Keep provider filtering, domain
restrictions and DRM controls enabled. If they reject playback, investigate
the entitlement rather than weakening the controls.

Verified primary documentation:

- [Bunny Get Video API](https://docs.bunny.net/reference/video_getvideo), server
  requests `GET https://video.bunnycdn.com/library/{libraryId}/videos/{videoId}`
  with `AccessKey`. It checks library identity and finished encoding status.
- [Bunny storage structure](https://docs.bunny.net/stream/storage-structure),
  documents the HLS playlist and thumbnail paths used by this adapter.
- [Bunny advanced token authentication](https://docs.bunny.net/cdn/security/token-authentication/advanced),
  documents HMAC-SHA256 and path-based directory tokens. Signing test vectors
  were generated by their official signer at commit
  `48ff1af0879c61b69a42c8db5ead76f849f5ef87`.
- [Bunny acceptable use policy](https://bunny.net/acceptable-use/), permits lawful
  adult content subject to its conditions. It does not grant redistribution rights.
- [Yoti quick start](https://developers.yoti.com/age-verification/quick-start),
  [session creation](https://developers.yoti.com/age-verification/create-a-session)
  and [results](https://developers.yoti.com/age-verification/results). The adapter
  enables Digital ID and document scan, requests `OVER`, preserves the hosted
  consent flow, and validates the method, SDK, reference, threshold and result.

## Deploy the separate API

For Cloudflare hosting, use [the Workers and D1 deployment option](cloudflare/README.md).
It shares the API policy and providers with this server, uses a new API hostname,
and preserves the existing GitHub Pages site. The instructions below cover Linux.

Use a Linux server with Node **24 LTS**, Caddy, HTTPS and persistent storage.
The API has no npm dependencies or build step. `node:sqlite` requires this
Node version. A server account and DNS access are necessary; neither was
attached to the development environment.

1. Choose a new same-site hostname, for example `portal-api.cjaffa.com`, and
   point only that hostname to the API server. Do not change `tools` DNS or
   the GitHub Pages configuration. A `workers.dev` origin is unsuitable for
   this cookie-based API because Safari restricts cross-site cookies.
2. Copy all root-level `.mjs` files in `xxx-api/` to
   `/opt/cj-private`. Create the `cj-private` service user and
   `/var/lib/cj-private`, owned by that user and mode `0700`.
3. Copy `.env.example` to `/etc/cj-private.env`, owned by root, mode `0600`.
   Set `API_ORIGIN`, the storage path and the provider settings using your
   deployment secret manager. The service manager reads this file. Never
   commit runtime environment files, actual license manifests or databases.
   Do not put provider keys into HTML, frontend configuration or shell arguments.
4. Configure your dedicated Bunny library and linked Pull Zone. Enable CDN
   token authentication using its token security key and set the allowed site
   to `tools.cjaffa.com` where the provider's domain controls apply. The page
   sends only its origin as a referrer. Verify unsigned playlist, segment and
   thumbnail requests are denied. Keep DRM-required videos out of this adapter.
   Set `BUNNY_CUSTOM_HLS_APPROVED=true` only after these checks and the rights
   review. The API read key and CDN signing key are different credentials.
5. Configure your Yoti organization, SDK and API key. Set the minimum age to
   the applicable policy, at least 18. Confirm its hosted ID methods and consent
   requirements for your audience. The callback is `https://tools.cjaffa.com/333/`.
   There is no self-attestation or test-verification fallback in production.
6. Install `cj-private.service`, then run `systemctl daemon-reload` and
   `systemctl enable --now cj-private`. The API listens only on
   `127.0.0.1:8787`. Install the supplied Caddy site configuration on the same
   host, adjusting only the new API hostname. Caddy stamps the client IP
   header and provides TLS. Do not expose port 8787 or forward caller-provided
   `X-Portal-Client-IP` headers. Keep access logs disabled or redact sensitive
   data; never log passwords, cookies, ID evidence or signed media URLs.
7. Create accounts in an interactive terminal, as the service user:

   ```sh
   PORTAL_DB=/var/lib/cj-private/portal.sqlite node /opt/cj-private/admin.mjs create-user your-username
   ```

   The password prompt hides input and requires at least 14 characters. There
   are no default accounts, default passwords or public registration endpoints.
8. Import each actual license manifest from a private location:

   ```sh
   PORTAL_DB=/var/lib/cj-private/portal.sqlite node /opt/cj-private/admin.mjs import-license /private/path/title.json
   ```

   Manifest shape, placeholders only:

   ```json
   {
     "providerVideoId": "<licensed Bunny video UUID>",
     "licenseReference": "<private contract evidence reference>",
     "category": "<approved category>",
     "startsAt": "<ISO 8601 UTC license start>",
     "endsAt": "<ISO 8601 UTC license end>",
     "countries": ["*"],
     "fullLengthAuthorized": true,
     "nativeHlsAuthorized": true,
     "drmRequired": false
   }
   ```

   Only use `["*"]` when the documented rights are worldwide. Regional
   declarations are accepted as records but remain unavailable. The current
   adapter supports at most 500 titles. Metadata is fetched only for listed
   video UUIDs, with bounded concurrency and a 30-second memory cache.
9. Verify `https://portal-api.cjaffa.com/healthz`, denied unauthenticated and
   unverified access, a real Yoti verification, a licensed title, URL expiry,
   seeking, resume, logout and unsigned-media denial. Test on an actual iPhone
   Safari and Android device before enabling the production connection.
10. Set only the public API origin in the `cj-portal-api` meta tag in
    `333/index.html`. Keep the API's `PORTAL_ORIGIN` at
    `https://tools.cjaffa.com`. Run the tests, pull `main`, commit and publish
    through the existing GitHub Pages branch workflow. Confirm `/333/` serves
    the new bytes with a cache-buster. The blank meta tag is intentional until
    the backend is ready: sign-in and playback remain unavailable.

## Security and operational limits

Sessions expire after eight hours; age grants after one hour or sooner with the
session. Every private endpoint checks both, and playback expiry is bounded by
the session, age grant and content license. CDN tokens last at most five minutes;
thumbnail tokens at most two. Removing a license or disabling an account stops
new authorizations immediately, but an already issued bearer URL can remain
usable until expiry. Browser buffering cannot be remotely revoked. If a contract
requires immediate revocation, add a provider-supported entitlement/DRM solution.

Favorites, history and account data are separate per user. Clearing history
removes that user's stored positions; subsequent watching writes new positions.
No private metadata or session token is persisted in frontend localStorage.
The public source contains only test fixture identities and neutral generated
clips, all confined to tests. No real catalog or media files ship with the portal.

The HTML uses a script-hash CSP, a restricted media/connect policy and no inline
event handlers. GitHub Pages cannot provide a private HTML response or custom
security headers for this folder. The server is the security boundary; the absence
of a navigation card, `noindex`, and the frontend gates are presentation controls.
The iframe explicitly allows fullscreen and picture-in-picture without changing
its viewport sizing or routes. The shell now mirrors native iframe navigation
with `replaceState`, avoiding the duplicate entry and lost Forward history found
in the original shell. Back and Forward are exercised in the browser suite.

Keep the database and its WAL sidecar on private persistent storage. Encrypt
server disks and backups, restrict administrator access, and use SQLite's backup
API or an offline snapshot rather than copying a live database file alone.
`PRAGMA user_version=1` records the schema version; the server refuses newer
databases. Future schema changes need explicit migrations and backup/restore tests.

Account management commands are `reset-password USERNAME` and
`disable-user USERNAME`; both revoke login sessions. `remove-license VIDEO_UUID`
removes that title and its favorites/history. No browser administrative endpoint
or provider-key input is exposed.

## Tests and local development

From the repository root:

```sh
cd tests
npm ci
node --test xxx-api-test.mjs
CJ_XXX_PORT=8861 node xxx-test.mjs
```

The browser suite requires Chromium and FFmpeg. It starts temporary loopback
frontend/API servers, generates a 60-second color-bar HLS clip, exercises the real
application and API with synthetic provider responses, and removes its database
and media afterwards. It checks authentication and age gates, search, categories,
pagination, favorites, persisted history, real HLS decoding, access renewal,
escaping, logout, absence from home navigation even with hidden tools revealed,
Back/Forward and viewport geometry. Use a **new port
on every rerun**, for example `CJ_XXX_PORT=8865`; the API uses the next port.
These fixtures do not verify a live provider account or iPhone hardware.

The vendored hls.js file has SHA-256
`7c47cd97d7a6e7b98d9623dd8ed9a6d45af4be4085e0c2001cd7175c2b4cfb07`.
Its upstream license is included at `333/HLS-LICENSE`. Keep the version pinned
and review updates before replacing it.

For an isolated manual backend test, `PORTAL_LOCAL=true` accepts only loopback
origins and uses a visibly separate, non-Secure local cookie. Never deploy local
mode, test fixtures, mock providers, or a test age grant. Production does not
contain a mechanism to force verification success.

After editing the inline application script, update the CSP hash in the meta tag.
The browser suite fails if the hash no longer matches and the browser blocks it.

## Rollback

Stop the API or blank its public origin in the frontend to close access. Revert
only the portal commit on `main`, leaving any later unrelated changes intact;
verify the live bytes after the Pages cache refresh. Restore a compatible private
database backup if necessary. Never roll back by replacing the whole existing site,
changing its CNAME, or attaching a Worker to `tools.cjaffa.com`.
